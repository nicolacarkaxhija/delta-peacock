The thesis, live

A gate, not a suggestion box.

Point it at a branch. It reads your guidelines from the target ref — so a pull request can't weaken the rules that judge it — reviews the diff, and returns exit 2 when a violation crosses your threshold. This is a real, unedited session against a demo cartridge repo.

feature/api-token — delta-peacock review 
delta-peacock review --fail-on MAJOR
BLOCKER  src/config.js:3  [no-secrets-in-code] Hard-coded credential
         Move this token to an environment variable; never commit secrets.
MAJOR    src/config.js:6  [rhino-compat] Optional chaining unsupported on the SFCC backend
         Rhino does not support ?.; use an explicit guard.

2 finding(s)
gate: failOn=MAJOR FAILED (2 at or above threshold)
exit code: 2

the contract

Findings cite a rule, or they don't gate

Every violation names the guideline it breaks and carries a stable fingerprint, so comments stay idempotent across re-runs and machines. The report is a plain JSON artifact — auditable, diffable, yours.

review.json
delta-peacock review --report review.json
{
  "gate": { "threshold": "MAJOR", "failing": 2, "failed": true },
  "findings": [
    {
      "severity": "BLOCKER",
      "file": "src/config.js", "line": 3,
      "guidelineId": "no-secrets-in-code",
      "fingerprint": "d1262ae38bb8"
    },
    {
      "severity": "MAJOR",
      "file": "src/config.js", "line": 6,
      "guidelineId": "rhino-compat",
      "fingerprint": "048174baee53"
    }
  ]
}

one-click fixes

Apply the suggestion to the working tree

When a finding carries a fix, fix applies it in place — validated against the exact line the reviewer saw, skipped with a reason if the file drifted. Or emit a --patch-file for CI to attach.

delta-peacock fix
delta-peacock fix --report review.json
applied  src/config.js:3
1 applied, 0 skipped
keep the reviewer in its lane

It knows what your linters already do

Guideline authoring gets fast feedback: guidelines lint validates the corpus and warns when a rule reads machine-checkable — the kind of thing a formatter enforces for free, so the model never wastes tokens on it.

delta-peacock guidelines lint 
delta-peacock guidelines lint
warning: guidelines/quotes.md: reads machine-checkable;
  a linter or formatter enforces this more cheaply than a review
guidelines ok: 3 usable, 0 disabled

The surface

One binary, thirteen verbs.

From delta-peacock --help — every command is composable, CI-friendly, and honours a hard --dry-run that never touches a PR.

review

Gate a branch against its guidelines. --staged, --bootstrap, --write-baseline.

audit

Review the whole tree, not just a diff. Adoption on day one.

describe

Write the PR description from the change, idempotently.

ask

Question the changeset in the terminal, one-shot or a session.

fix

Apply report suggestions to the tree or a patch file.

waive

Insert an in-code waiver: a deliberate, always-reported exception.

learn

Turn team reactions into proposed guideline drafts.

stats

Per-contributor findings, normalized — a coaching aid.

guidelines

Lint, coverage stats, packs, and legacy import.

doctor

Validate the whole install before you spend a token.

init

Scaffold config, a guideline, a CI snippet. --walkthrough.

bench

Score the reviewer against benchmark cases.

config

Resolve and print the effective configuration.
